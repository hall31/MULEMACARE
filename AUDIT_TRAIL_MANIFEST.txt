=============================================================================
DATA MODEL
=============================================================================

TABLE: audit_logs

Columns:
  id                VARCHAR(64) PRIMARY KEY
  timestamp         DATETIME(UTC) DEFAULT now()
  action            VARCHAR(32) — created|approved|rejected|executed
  actor_id          VARCHAR(64) — user.id or "system"
  actor_role        VARCHAR(32) — MEMBER|OPS|ADMIN|system
  agent_proposal_id VARCHAR(64) — FK to agent_proposals
  old_status        VARCHAR(32) [nullable] — previous status
  new_status        VARCHAR(32) — new status
  reason            TEXT [nullable] — decision note
  metadata          JSON [nullable] — extensible context

Indexes:
  - (timestamp) — for time-range queries
  - (action) — for filtering by event type
  - (actor_id) — for user accountability reports
  - (agent_proposal_id) — for per-proposal trails (PRIMARY)

Creation: Automatic via init_db() on app startup (SQLAlchemy)

=============================================================================
API ENDPOINT
=============================================================================

GET /api/v1/action-center/proposals/{proposal_id}/audit-trail

Request:
  - Auth: Bearer token (OPS|ADMIN|MEMBER roles)
  - Params: proposal_id (UUID)

Response 200:
  {
    "proposal_id": "uuid",
    "audit_trail": [
      {
        "id": "log-id",
        "timestamp": "2026-08-30T14:23:45.123Z",
        "action": "created|approved|rejected|executed",
        "actor_id": "user-id or system",
        "actor_role": "MEMBER|OPS|ADMIN|system",
        "agent_proposal_id": "proposal-id",
        "old_status": "pending" or null,
        "new_status": "pending|approved|rejected|executed",
        "reason": "decision note or reason",
        "metadata": { ... }
      },
      ...
    ]
  }

Response 404: Proposal not found

=============================================================================
LIFECYCLE EVENTS
=============================================================================

EVENT 1: created
  Trigger: POST /proposals
  Action: "created"
  Actor: User/Agent creating proposal
  Status: None → pending
  Metadata: agent_name, action_type

EVENT 2: approved
  Trigger: POST /proposals/{id}/decide with decision="approved"
  Action: "approved"
  Actor: OPS/ADMIN user
  Status: pending → approved
  Note: User's decision note

EVENT 3: rejected
  Trigger: POST /proposals/{id}/decide with decision="rejected"
  Action: "rejected"
  Actor: OPS/ADMIN user
  Status: pending → rejected
  Note: User's rejection reason

EVENT 4: executed
  Trigger: Automatic after approved (if execution succeeds)
  Action: "executed"
  Actor: system
  Status: approved → executed
  Note: Execution success details

CONTRACTS & GUARANTEES
=============================================================================

✓ TRACEABILITY
  - Every status change is logged
  - Timestamps are server-side (UTC)
  - No events can be silently omitted

✓ ACCOUNTABILITY
  - Every decision captures who decided (actor_id, actor_role)
  - Every decision captures why (reason/note)
  - Every decision is timestamped

✓ IMMUTABILITY
  - Audit logs are insert-only at application layer
  - No update or delete methods in repository
  - Chronological ordering is guaranteed
  - Database constraints can be added (optional)

✓ EXTENSIBILITY
  - Metadata JSON field for future context
  - Agent version, prompt hash, feature flags captured
  - No schema migration needed for metadata changes

PERFORMANCE CHARACTERISTICS
=============================================================================

Write Performance:
  - 3 inserts per proposal lifecycle (created, approved/rejected, executed)
  - Blocking waits (flush to DB)
  - Negligible impact (<10ms per proposal)

Read Performance:
  - Single query for audit trail: O(n) where n = logs per proposal
  - Typical n = 2-4 logs
  - Query time: <50ms (indexed on agent_proposal_id)

Storage:
  - ~500 bytes per log entry (metadata varies)
  - 10,000 proposals = 20,000-40,000 logs = 10-20 MB
  - No archival needed for 1-2 years of data
